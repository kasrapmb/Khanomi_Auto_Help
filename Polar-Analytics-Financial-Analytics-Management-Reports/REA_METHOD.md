# Stage 3 REA investigation — Polar Analytics

## Target
Polar Analytics financial analytics and management reporting.

## Skill
Read `REA_skills_Codex-main/REA-Skills/reverse-engineer-anything/SKILL.md` from https://github.com/zia62381-crypto/rea_codex.

The skill explains that inspecting a running proprietary application requires a REA runtime/browser capture, or a supplied artifact for static analysis. The skill instructions alone do not install or expose the REA MCP server. No REA capture tools were available in this conversation; therefore no authenticated dashboard capture, shipped JavaScript bundle analysis, or proprietary source retrieval was performed.

## Public feature evidence
- Polar custom reporting and metric formula builder: https://www.polaranalytics.com/features/custom-report
- Finance-grade metrics, including net revenue, margin, ad spend and finance reports: https://www.polaranalytics.com/post/ecommerce-analytics-without-a-data-team-is-it-possible-in-2026
- Net revenue, COGS, advertising spend and profit distinctions: https://www.polaranalytics.com/post/shopify-reports-explained-sales-inventory-and-pos-data-in-one-place

## Recreated components
- Finance overview with metric cards and date/channel filtering
- SVG trend visualization and financial profit bridge
- Channel profitability table
- Executive management highlights
- Adjustable cost scenario and CSV export

## Scope and limits
This is an independent educational prototype with deterministic synthetic data. It is **not** a source-code clone of Polar, is not connected to Shopify, Meta, Google, Snowflake or any Polar account, and does not claim pixel-perfect UI matching. Real financial reconciliation, governed metrics, accounting rules and multi-source ingestion are outside scope.
