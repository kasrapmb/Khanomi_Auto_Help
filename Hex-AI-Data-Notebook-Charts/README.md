# Hex — Data Notebook, Charts & Local Query Helper

بازسازی مستقل و قابل اجرای یک **فضای کاری تحلیل داده با SQL، نمودار و دستیار پرسش**، الهام‌گرفته از Hex. نویسندهٔ کد و commitها: `kasrapmb`.

**این پوشه سورس اصلی Hex نیست.** سایت مرجع در این محیط HTTP 403 برگرداند؛ سورس یا ظاهر زندهٔ محصول ضبط و بازیابی نشده است. این پیاده‌سازی مستقل است و دادهٔ نمونه دارد.

## اجرا

Node.js 20.19+ یا 22.12+ و npm لازم است. از همین پوشه:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run dev -- --host 127.0.0.1 --port 5210
```

برای خروجی production:

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4210
```

Vite فایل worker و SQLite WASM را نیز در build قرار می‌دهد. برنامه را از HTTP/HTTPS اجرا کنید؛ بازکردن مستقیم `index.html` با `file://` مسیر اجرای این پروژه نیست. backend، حساب Hex، API key و warehouse لازم نیست.

## قابلیت‌های واقعی

- **Notebook:** سلول متن قابل ویرایش، SQL واقعی، جدول نتیجه و نمودار وابسته به همان نتیجه.
- SQLite داخل worker مرورگر اجرا می‌شود؛ داده‌ها براساس متن query محاسبه می‌شوند، نه با نتیجهٔ ثابت یا شبیه‌سازی SQL.
- پارامتر `:region` با انتخاب منطقه هنگام اجرا bind می‌شود.
- تغییر SQL یا پارامتر خودکار نتیجه را عوض نمی‌کند؛ تا اجرای بعدی، نتیجهٔ موفق قبلی با برچسب واضح نمایش داده می‌شود.
- خطای syntax یا نام ستون، نتیجهٔ قبلی را حذف نمی‌کند؛ پیام خطا و منشأ داده قابل مشاهده‌اند.
- لغو query، محدودیت زمانی worker و اجرای دوباره بدون تغییر دادهٔ منبع.
- جدول با جست‌وجو، مرتب‌سازی عددی/متنی، صفحه‌بندی، نمایش نوع‌های استنباط‌شده و CSV واقعی.
- نمودار میله‌ای/خطی با انتخاب محورهای موجود در نتیجه و پشتیبانی از مقدار منفی.
- **App preview:** نمایش خواندنی تحلیل موفق قبلی، بدون ویرایشگر SQL.
- **Data:** طرح منبع، مرور ردیف‌ها و CSV دادهٔ نمونه.
- تاریخچهٔ ۸ اجرای آخر همان نشست؛ بازیابی query نیازمند اجرای صریح برای تغییر نتیجه است.
- ذخیرهٔ محلی draft و یادداشت، خروجی JSON تنظیمات دفتر، میان‌بر `Ctrl/Cmd + Enter` برای اجرا و `Ctrl/Cmd + K` برای دستیار.
- منوی موبایل، پنل دستیار قابل باز و بسته‌شدن و اسکرول داخلی جدول/کد.

## دستیار چه کار می‌کند؟

پنل صریحاً با برچسب **Local query helper — Template-based · no LLM connected** نمایش داده می‌شود.

این نسخه **مدل هوش مصنوعی متصل ندارد**. سؤال‌های پشتیبانی‌شده را با کلیدواژه به یکی از چهار SQL الگو تبدیل می‌کند:

- روند درآمد ماهانه
- درآمد بر اساس منطقه
- عملکرد دستهٔ محصول
- سفارش‌های اخیر

ابتدا SQL پیشنهاد می‌شود؛ فقط پس از انتخاب **Run suggested query**، SQL واقعاً اجرا و پاسخ کوتاه از ردیف‌های برگشتی ساخته می‌شود. سؤال نامرتبط، پاسخ ساختگی دریافت نمی‌کند و دسته‌های قابل پشتیبانی توضیح داده می‌شوند. سؤال‌ها به سرویسی خارج از مرورگر ارسال نمی‌شوند.

## منبع و محدودیت SQL

۲۴۰ سفارش ساختگی با ۸ ستون در `src/data.js` تولید می‌شوند. مبلغ‌ها در منبع integer cents هستند؛ query پیش‌فرض آن‌ها را به دلار تبدیل و درآمد و سود ناخالص ماهانه را جمع می‌کند. سود ناخالص این داده فقط درآمد منهای هزینهٔ محصول است، نه سود خالص کسب‌وکار.

- فقط **یک دستور SELECT** پذیرفته می‌شود. `WITH`، DDL، DML و PRAGMA به‌عنوان دستور کاربر پشتیبانی نمی‌شوند.
- SQLite در حالت `query_only` است؛ در هر اجرا یک پایگاه تازه از دادهٔ ثابت ساخته می‌شود.
- طول query حداکثر ۱۰٬۰۰۰ کاراکتر و زمان worker حداکثر ۸ ثانیه، شامل آماده‌سازی، است.
- نتیجه حداکثر ۵۰۰ ردیف دارد. در صورت truncation، جدول، نمودار و CSV صریحاً از همان نتیجهٔ محدود استفاده می‌کنند.
- نمودار حداکثر ۴۰ ردیفِ اول نتیجه را رسم می‌کند و آن را اعلام می‌کند؛ برای تجمیع باید SQL بنویسید.
- نام ستون‌های نتیجه باید یکتا باشد. نمودار به حداقل یک ستون عددی نیاز دارد.
- فقط پارامتر `:region` از کنترل برنامه تأمین می‌شود.
- جست‌وجو و مرتب‌سازی جدول فقط نمایش و CSV را تغییر می‌دهند، نه KPI یا نمودار. CSV محدود به صفحهٔ جاری نیست.
- نوع ستون‌های نتیجه از مقادیر برگشتی استنباط می‌شود؛ نتیجهٔ خالی نوع نامعلوم دارد. طرح منبع در Data از تعریف واقعی جدول می‌آید.
- مقدارهای `_cents` در جدول به دلار نمایش داده می‌شوند، اما CSV مقدار خام SQL را صادر می‌کند.

SQL.js نسخهٔ `1.15.2` با مجوز MIT استفاده شده است. مجوز، integrity بسته و SHA-256 فایل WASM در `licenses/` حفظ شده‌اند.

## ذخیره و خروجی

query، یادداشت plain text، منطقه و نوع نمودار در `localStorage` همان origin ذخیره می‌شوند. بعد از refresh، query ذخیره‌شده دوباره واقعاً اجرا می‌شود؛ نتایج یا تاریخچه به‌عنوان دادهٔ تأییدشده ذخیره نمی‌شوند. داده‌ها بین مرورگرها/کاربران یا تب‌ها همگام نیستند.

JSON خروجی، فرمت مخصوص همین مطالعه (`hex-study-v1`) است؛ فرمت رسمی Hex نیست و قابلیت import پیاده‌سازی نشده است. محورهای انتخابی در JSON می‌آیند، ولی ذخیرهٔ محلی آن‌ها را نگه نمی‌دارد؛ پس از اجرا، محورهای معتبر از ستون‌های نتیجه انتخاب می‌شوند.

## تست مرورگر

ابتدا build کنید. Python 3.10+، Playwright و Chromium لازم است:

```sh
python3 -m venv .runtime/test-venv
.runtime/test-venv/bin/pip install -r requirements-test.txt
CHROMIUM_PATH=/usr/bin/chromium .runtime/test-venv/bin/python tests/browser_smoke.py
```

در محیط آماده، `python3 tests/browser_smoke.py` هم اجرا می‌شود. تست‌ها preview موقت خود را اجرا و متوقف می‌کنند. انتظارهای مالی و SQL با SQLite مستقل Python روی دادهٔ خام بررسی می‌شوند؛ نتایج در `docs/VALIDATION.md` است.
